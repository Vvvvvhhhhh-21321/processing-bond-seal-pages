# 阶段二：接收回章页合集后回拼

## 输入与命令

输入必须包含第一阶段原处理批次和一个回章页合集 PDF。先完成 `SKILL.md` 的 `complete` 前置检查，再运行；仅在用户提供统一落款日期时追加日期参数：

```text
"<python>" "<skill-root>/scripts/run_bond_seal_pages.py" complete "<处理批次目录>" "<回章页合集.pdf>" "<输出目录>"
"<python>" "<skill-root>/scripts/run_bond_seal_pages.py" complete "<处理批次目录>" "<回章页合集.pdf>" "<输出目录>" --signing-date YYYY-MM-DD
```

## 脚本行为

- 先校验处理批次中的路径、页数与哈希，并复用第一阶段完整底稿 PDF。
- 优先读取回章页文字层；不足时调用本机 PP-OCRv6 small。OCR 只识别标题，不改变 PDF 页面。
- 独立匹配乱序页面；相似度不低于 90 的唯一候选自动处理。
- 同标题先逐页配对；回章页数量不足时允许复用已匹配页面。
- 对已匹配页面按需补齐空缺的年、月、日；已有组成部分保持原样，无法安全落位时记录日期异常但仍可回拼。
- 直接用回章页原始 PDF 页面对象替换完整底稿 PDF 的最后一页，不缩放、裁切或重新栅格化。
- 覆盖输出目录中的旧生成结果，生成逐份盖章版 PDF 和 `processing-report.html`。
- 输出目录已存在时不增加人工暂停；脚本只覆盖 `completed-pdfs` 与 `processing-report.html` 等本流程生成物，保留目录中的无关文件。

低置信度、歧义、无标题、缺页和单文件失败进入最终处理清单，当前批次继续完成。流程中间不暂停让用户逐页复核，也不按顺序猜测或强制匹配；最后统一让用户打开处理清单核对。

## 验证

核对 JSON 与文件：

- `total` 等于处理批次中的全部底稿记录数。
- `outcomes`、`date_outcomes`、`unused_pages` 与 `ocr_failures` 都已报告。
- 每个 `completed` 项都有对应盖章版 PDF。
- `items` 数量等于 `total`；逐项核对 `status`、`output_path`、`reason` 和 `date_status`，不要把状态汇总对象当作逐项列表。
- `report` 指向存在的 `processing-report.html`，且清单逐份显示底稿文件、待盖章页码、回章页码、标题、相似度、日期结果、状态、原因和输出位置。
- 打开 HTML 确认没有缩略图或嵌入页面图片；原底稿、待盖章页合集、回章页合集和成功输出均按可用情况提供可直接打开的本地文件链接。

向用户报告成功数、各异常状态数量、盖章版 PDF 目录和处理清单位置。处理清单不生成缩略图；发现问题时直接打开其中链接的原底稿、待盖章页合集、回章页合集或输出 PDF。

完成标准：处理清单覆盖处理批次中的每份底稿，成功文件均存在，所有跳过与失败都有状态和原因。`partial` 表示批次已尽可能完成，不等于整批失败。
