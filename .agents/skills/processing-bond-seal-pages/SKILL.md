# 债券底稿盖章页处理

## 目标

用一个**处理批次**稳定连接盖章闭环：先生成待盖章页合集；客户返回回章页合集后，先生成一份**日期确认稿**并等待用户确认，再复用已保存的匹配关系完成回拼和处理清单。

脚本负责可重复、机械和高风险的文件操作；模型只判断业务阶段与范围、协助选择运行环境、在日期确认关口提示用户并解释最终异常。模型不自行重写 PDF、猜测低置信度匹配、绕过批次校验或跳过用户确认。

## 判定范围和阶段

当前业务对象是**底稿文件**：每份 `.doc` 或 `.docx` 只有一张盖章页，固定为最后一页。

| 已有输入 | 执行分支 |
|---|---|
| 底稿文件目录 | `prepare`：生成处理批次与待盖章页合集 |
| 处理批次 + 回章页合集 PDF | `date-review`：匹配、补日期并生成一份完整日期确认稿；不得回拼 |
| 处理批次 + 日期确认目录 + 用户在看到确认稿后的明确确认 | `finalize --confirmed`：复用已保存的页码映射完成回拼 |

遇到发行文件或一份文件包含多张签字页/盖章页时，退出当前流程，且不运行入口；说明这是后续扩展方向，实施前需另行定义多张签字页的发现、排序、文件内映射和回拼规则。缺少原处理批次时，请用户提供第一阶段完整目录；处理批次是业务接缝，不重新转换 Word 或临时重建映射。

完成标准：已明确选择一个分支，且输入属于当前底稿文件边界。

选择 `prepare` 时，还必须取得用户对重复文件策略的明确选择：

- `keep`：所有 Word 都参与整个流程。
- `deduplicate`：在任何 Word 转换前按源文件 SHA-256 分组，每组只保留路径排序最前的一份；其他重复文件不转换、不进入处理批次、不匹配，也不生成最终文件。

如果用户没有说明，先询问“保留全部 Word，还是按 Word 文件哈希排除重复文件？”，并停止等待回答。不得根据“标题相同”“纸质底稿”或历史默认值代替用户选择。文件名、标题和页面外观不参与去重判断。

然后只读取对应阶段引用：

- 选择 `prepare` 时，完整读取 [`references/prepare.md`](references/prepare.md) 后执行。
- 选择 `date-review` 或 `finalize` 时，完整读取 [`references/complete.md`](references/complete.md) 后执行。

统一入口仍保留旧版 `complete` 命令用于兼容已有调用，但本 skill 不得调用它；它会绕过日期确认关口。

## 统一入口

将本文件所在目录记为 `<skill-root>`，统一入口是：

```text
<skill-root>/scripts/run_bond_seal_pages.py
```

将前置检查最终选中的解释器记为 `<python>`。动态使用真实路径，不写死某台机器的 Python、Conda 或应用路径。

命令输出 UTF-8 JSON：

- 退出码 `0`：当前命令已完成。`date-review` 的 `status` 固定为 `awaiting_confirmation`，表示必须停下等待用户；`finalize` 的 `status` 可能是 `completed` 或 `partial`。
- 退出码 `2`：前置检查未通过，业务函数没有启动。
- 退出码 `1`：批次级失败；保留错误信息，不宣称完成。

## 前置检查与安装同意

在所选分支开始前运行对应检查：

```text
"<python>" "<skill-root>/scripts/run_bond_seal_pages.py" preflight --stage prepare
"<python>" "<skill-root>/scripts/run_bond_seal_pages.py" preflight --stage date-review
"<python>" "<skill-root>/scripts/run_bond_seal_pages.py" preflight --stage finalize
```

只有 `prepare` 检查平台 Word 转换器；`date-review` 和 `finalize` 不要求 Word/LibreOffice。按顺序处理未通过结果：
`date-review` 会实际导入 `numpy` 与 `cv2`，其中 `cv2` 对应安装包 `opencv-python-headless`；不要因为找到了包目录就跳过导入检查。


1. 向用户说明每个缺失项、目标 Python 和安装影响。
2. 报告要求改用另一解释器时，用报告中的完整路径重跑；解释器 A 的检查结果不能授权解释器 B 处理。
3. 出现同优先级候选时列出候选并让用户选择。脚本已优先当前激活的 Conda/Anaconda，其次当前执行环境，再其次系统候选。
4. 用户明确同意安装后，才在同一命令追加 `--approved-install-plan`。先展示计划，再逐条执行用户同意的命令。
5. 安装后重新运行普通检查，直到 JSON `status` 为 `ready`。

环境变化保持单点、可见：只修改唯一选中的 Python；机器没有 Python 时按计划使用 winget、Homebrew 或人工安装；不创建私有回退环境，也不向多个 Python/Conda 环境同时安装。

完成标准：JSON `ready` 为 `true`，且当前解释器就是 `selected_python`。用户拒绝安装时停止并报告，不创建处理批次、日期确认稿或回拼结果。

## 判断边界

模型可以选择阶段、识别是否超出底稿文件范围、向用户解释环境候选，并在日期确认关口与最终清单阶段和用户交互。

脚本决定文件遍历、Word 源文件哈希与去重、Word 转换、最后一页提取、哈希校验、文字/OCR 路由、90 分阈值、同标题分配与复用、原始日期锚点提取、页面图像配准、日期落位、确认稿生成、页数校验、PDF 页面替换和 HTML 清单生成。低置信度、歧义、无标题、缺页和单文件失败继续进入结果，不暂停逐页匹配。

回章页匹配后，以处理批次中对应完整底稿 PDF 的最后一页作为日期模板：从未盖章模板取得完整“年、月、日”坐标，同时计算图像特征配准与灰度相关性配准，并按日期区域和整页对齐效果选择较可靠结果。两套结果一致时正常落日期；结果分歧或只有一套可用时仍落日期，但标记 `filled_needs_review`；只有两套都无法产生可用坐标时才保留原页并记录日期失败。印章遮挡回章页日期字样时不要让模型猜坐标，也不要另写临时 OCR 脚本。

日期确认关口只允许模型在生成确认稿后暂停一次。模型直接采用 `date-review` JSON 中的 `confirmation_message`，并逐页列出 `review_pages_requiring_attention`，不要自行省略重点核对页码。用户可以修改页面内容；模型必须提醒不要增删页面或改变页面顺序。没有取得用户在看到确认稿后的明确确认时，不得执行 `finalize`，也不得把最初的处理请求视为事后确认。

当前能力不检查是否已经盖章，也不判断印章真伪或盖章主体。表格页识别代码保留给未来发行文件扩展，但不接入当前底稿文件流程。
