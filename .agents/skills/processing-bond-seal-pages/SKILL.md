# 债券底稿签署页项目处理

## 目标

把底稿签署工作组织为一个可自然语言续接的**签署页处理项目**。用户只描述现有材料和确认结果；不要要求用户理解或输入内部命令、批次目录或英文技术文件名。

确定性脚本负责移动文件、Word 转 PDF、哈希、合集、OCR、匹配、Times New Roman 落字、坐标安全校验、回拼、清单和回收站操作。模型负责识别当前阶段、根据文件名提示疑似分组错误、视觉复核日期位置、解释异常并取得必要确认。

## 模型建议与能力降级

推荐使用具备图像输入能力的 GPT-5.6 Sol medium；成本优先时可用 GPT-5.6 Terra xhigh。当前 Skill 元数据不能强制模型或推理档位，因此这是推荐基线，不是虚假的硬门槛。

支持图像输入时，模型必须复核所有脚本新增日期的页面。不能接收图像时，调用内部“跳过视觉复核”动作，明确告诉用户已跳过，并把所有补字页列为人工重点核对页；确定性流程仍可继续。

## 业务边界

- 当前只处理**底稿文件**：每份 `.doc` 或 `.docx` 的最后一页是唯一签署页。
- **发行人说明性文件**由发行人盖章；**项目组分析文件**由项目组签字。两者是独立签署文件组，合集、签署回页、日期、确认稿、成果和处理清单不得混用。
- 项目可以只有一组，也可以同时有两组。用户明确提供各组目录，不根据 Word 正文自动分类。
- 遇到一份文件包含多张签字页的发行文件时停止，说明当前版本不支持，不要猜页码。
- 不判断印章真伪、是否已盖章或签字人身份。

## 首先判断现有状态

根据用户提供的路径选择自然阶段：

| 现有材料 | 下一步 |
|---|---|
| 一个或两个原始 Word 目录，没有签署页处理项目 | 新建项目；若还没有签署回页，准备待签署材料 |
| 有效签署页处理项目 | 读取项目状态，只继续未完成阶段 |
| 原始 Word + 已返回签署页，但没有原处理数据 | 新建项目后补建对应签署文件组 |
| 项目已生成日期确认稿 | 先完成视觉复核，再展示确认稿并等待用户确认 |
| 用户已看到日期确认稿并明确确认 | 回拼对应签署文件组 |
| 所有实际存在的签署文件组均完成 | 报告成果；另行询问是否清理处理数据 |

同名目录只有包含有效项目状态时才能续接；普通非空目录不得接管或混入文件。续接时必须读取状态并报告“已完成、待继续、需确认”，不得从头重做。

## 项目初始化与分组检查

项目名默认取共同项目文件夹名称，用户可自然语言覆盖。初始化前：

1. 列出两个输入目录中递归发现的 Word 文件名。
2. 只依据文件名判断是否存在明显疑似分错组；不要读取正文做分类。
3. 有疑问时向用户展示当前组、建议组和理由，等待确认。无疑问时直接继续。
4. 说明初始化会在同一项目文件夹内新建项目框架并移动 Word；取得确认后才执行。

初始化只移动 `.doc`/`.docx`，保留相对目录；其他文件留在原处。目标必须是新建空目录，不能覆盖。移动失败后停止转换并报告已移动与未移动现状，不自行复制或回滚。

读取并遵循 [`references/prepare.md`](references/prepare.md) 完成初始化和待签署材料。

## 重复文件策略

正常准备每个实际存在的签署文件组前，询问一次：

- **每份单独签署**：每份 Word 在合集中独占一页。
- **完全重复文件复用签署页**：同组 SHA-256 完全相同的 Word 只在合集中占一页，共享对应签署回页，但每份 Word 都生成最终签署版底稿。

不按标题、文件名或页面外观判断重复，不跨发行人与项目组复用。补建处理数据时不再询问策略：所有当前 Word 都保留，完全重复 Word 自动复用已有签署回页。

## 日期处理与视觉校准

收到某组签署回页后，先保存为该组业务原件，再让脚本完成 OCR、乱序匹配和初始日期落字。新增日期必须使用真正的 Times New Roman；找不到字体时停止，不得使用 Times-Roman、Helvetica 或其他近似字体。

脚本生成日期确认稿后：

1. 取得所有脚本补字页的原始回页图和脚本结果图。
2. 支持图像时逐页查看，检查是否重复落字、偏离“年/月/日”、遮挡标签或正文、落在印章或签字的不合适区域。
3. 模型只能返回新增数字的 `x`、`y`；日期值、字体、字号、颜色和页面其他内容锁定。
4. 内部工具从原始签署回页重生成候选页并执行硬性校验，不能在上一轮结果上叠加。
5. 模型复看候选页并明确给出“通过”“需调整”或“无法判断”。通过且硬性校验成功即完成；需调整时继续，最多五轮；无法判断时立即恢复脚本初始页并转人工核对。
6. 五轮仍未确认时恢复脚本初始位置并标记人工核对。任何建议未通过硬性校验时也立即恢复脚本初始页，不保留此前模型候选页。

完成模型复核后，把日期确认稿路径、跳过状态和所有重点页一次性告诉用户。提醒可人工修改，但不能增删页面或改变顺序。随后停止，等待用户在看到确认稿后明确确认；最初的处理请求不算事后确认。

读取并遵循 [`references/complete.md`](references/complete.md) 完成签署回页、视觉校准、回拼、补建和清理。

## 确认关口

存在两个相互独立的确认：

1. **日期确认**：只授权把当前日期确认稿按保存映射回拼。确认后不重新 OCR、匹配、识别日期或视觉校准。
2. **清理确认**：所有实际提供的签署文件组完成后单独询问。用户确认后只把“处理数据_请勿删除”移入系统回收站。

如果没有图像复核、存在失败或仍有重点页，回拼或清理前要逐项说明，并取得用户明确接受。清理不得删除原始 Word、待签署合集、签署回页原件、日期确认稿、最终底稿或处理清单。

## 用户可见成果

每个实际存在的签署文件组只展示：

- `原始Word/`
- `<项目名>_发行人待盖章页合集.pdf` 或 `<项目名>_项目组签字页合集.pdf`
- `<项目名>_发行人回章原件.pdf` 或 `<项目名>_项目组回签原件.pdf`
- 对应日期确认稿
- 对应盖章版或签字版底稿目录
- 对应中文处理清单

技术过程数据集中在 `处理数据_请勿删除/`；根目录只额外保留小型 `项目状态_project.json`，使过程数据移入回收站后仍能识别项目已清理。最终 PDF 去掉 `.doc/.docx`；同目录下同名 `.doc` 与 `.docx` 分别追加 `（doc）`、`（docx）`。

## 报告方式

每一步先报告业务结果，不展示内部命令。至少说明：当前项目与签署文件组、完成阶段、生成或保留的用户可见文件、失败或重点页、下一次需要用户提供或确认的内容。只有脚本返回成功且文件校验存在时才宣称完成。
