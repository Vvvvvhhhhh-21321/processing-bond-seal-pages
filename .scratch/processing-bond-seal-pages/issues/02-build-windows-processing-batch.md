# 02 — 从 Windows Word 生成处理批次

**What to build:** 让 Windows 用户可以把一批 `.doc` 和 `.docx` 底稿文件转换为完整 PDF，逐份提取最后一页并生成待盖章页合集，同时保存第二阶段所需的处理批次信息。

**Blocked by:** 01 — 修复 PDF 原样回拼契约与测试基线。

**Status:** resolved

- [x] Windows 上通过本机 Microsoft Word 后台转换 `.doc` 与 `.docx`，不显示窗口、不保存或修改原 Word。
- [x] 每份成功转换的底稿保留完整 PDF，并将最后一页逐份加入待盖章页合集。
- [x] 同标题底稿不去重，待盖章页合集页数与成功处理的底稿数量一致。
- [x] 处理批次记录底稿文件标识、相对位置、标题、合集页码、完整 PDF 页数和文件校验值。
- [x] 单个文件转换、读取或提取失败时记录失败并继续处理其他文件。
- [x] 重复运行可覆盖同一位置的旧生成结果，但原 Word 始终保持不变。
- [x] 端到端测试覆盖成功文件、重复标题文件和转换失败文件混合存在的批次。

## Answer

已实现 Windows Microsoft Word 后台只读转换与“底稿目录 → 处理批次”公开入口。处理批次保留逐份完整 PDF，按底稿逐页生成不去重的待盖章页合集，并以 UTF-8 JSON 记录底稿标识、相对位置、标题、合集页码、页数和校验值；单文件失败会记录后继续。重复运行只覆盖本流程生成物，并拒绝可能删除原 Word 的危险目录关系。

实现提交：`aad2c84`、`19af140`、`9e1b86c`、`ef30a11`。完整测试共 43 项：42 项通过；1 项真实 Word 冒烟测试在未配置 `BOND_SEAL_PAGES_WORD_SMOKE_WORKING_PAPER` 且当前 Python 缺少 `pywin32` 时跳过。标准与规格双轴复核均无剩余阻断发现。
