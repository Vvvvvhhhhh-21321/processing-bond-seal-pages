# 08 — 完成 Skill 两阶段入口与验收

**What to build:** 让用户能够通过完整的 Skill 说明和两个明确入口执行“生成处理批次”与“接收回章页后回拼”，并用真实底稿样本验证整个流程符合规格。

**Blocked by:** 06 — 生成可筛选的 HTML 处理清单；07 — 完成跨平台前置检查与 macOS 转换。

**Status:** resolved

- [x] Skill 描述明确说明适用场景、触发语句、输入文件、两个阶段和当前底稿文件范围。
- [x] 第一阶段入口完成前置检查、Word 转换、处理批次和待盖章页合集生成，并向用户清楚报告结果。
- [x] 第二阶段入口完成批次校验、文字层或 OCR 识别、标题匹配、日期补齐、原样回拼和 HTML 清单生成。
- [x] Skill 不把发行文件、印章真伪检查、Word 回写或处理中人工复核描述为已支持能力。
- [x] Windows 真实样本完成两阶段端到端验收，macOS 转换路径具备可重复的验证步骤。
- [x] 端到端验收覆盖乱序、缺页、同标题不去重、同标题复用、扫描页、低置信度、部分日期和单文件失败。
- [x] 所有自动化测试通过，既有表格页识别能力保持可用但不接入当前底稿流程。
- [x] 最终文档使用领域术语表中的规范名称，并与两份架构决策及正式规格一致。

## 实施结果

Skill 现提供一个统一脚本入口和 `preflight`、`prepare`、`complete` 三个命令。主说明只负责判定当前底稿文件范围、选择阶段和解释结果；两个阶段的机械步骤、退出条件、命令及完成核对分别下沉到按需读取的参考文档。发行文件多签字页场景会在运行入口前安全退出，并明确后续扩展需另行定义签字页发现、排序、文件内映射和回拼规则。

第二阶段前置检查不再要求 Word/LibreOffice 或 Windows `pywin32`，但仍检查 PDF、RapidOCR、ONNX Runtime 和 PP-OCRv6 small。统一入口固定输出 UTF-8 JSON，并逐份返回状态、回章页码、相似度、日期结果、原因和输出位置，便于较弱模型进行确定性核对。处理清单不生成缩略图，直接提供本地文件链接。

Windows 真实样本验收处理 44 份 `.doc`/`.docx` 底稿和 44 页纯扫描回章页合集：第一阶段 44/44 转换成功，第二阶段 44/44 完成，0 个未使用页、0 个 OCR 失败；原底稿哈希保持不变，44 个回章页页面对象全部原样保留，HTML 共 44 条记录且不含图片。macOS LibreOffice 路径有契约测试和条件式真实文件冒烟测试。

自动化测试最终运行 105 项，全部通过，3 项需要外部真实文件或对应平台的冒烟测试按条件跳过；Skill 结构校验与 `git diff --check` 通过。技能评测第二轮覆盖准备、乱序缺页回拼和发行文件范围退出三个场景，新版 13/13 条断言通过，旧模板通过率为 17.8%。Standards 与 Spec 两条代码审查最终均无 P0–P2 阻塞。
